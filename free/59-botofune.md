# JavaScriptからの護身術

JavaScriptを書くのってめんどくさくないですか。
フロントエンドのライブラリやフレームワークを使わない開発をするときなんか特に。
例えばRuby on RailsでJavaScriptをゴリゴリと書かざるを得ないって状況に遭遇したら、
「Rails使ってんだからRuby以外書きたくね～。」
って、私は思ってしまうものです。
また、私の周りにはJavaScriptが苦手であったり、「好きじゃない」という人もいます。

それでもJavaScriptというものは、頻繁に開発者の目の前に現れて、
「さぁ、私を書け！それを実装するには私が必要だぞ！さぁ、私を書け！」
と迫ってきます。
そこで使えるのが、JavaScriptから身を護る術──「JavaScriptからの護身術」です。
ということで「JavaScriptのことを好きになれないし、書きたくない」という人に向けて、JavaScriptが必要そうな実装を、JavaScriptを使わずに実装する術を伝授します。
では、JavaScriptからの護身術の稽古を始めましょう。

## JavaScriptからの護身術のデモンストレーション

https://js-defense.botofune.com
上記のページで、以下の9種類のJavaScriptからの護身術のデモンストレーションを体験できます。

1. ドロワーメニュー
2. モーダルダイアログ
3. ドロップダウン
4. フィルタリング
5. リアルタイムバリデーション
6. SPA的ページ遷移アニメーション
7. オンボーディングツアー
8. トースト
9. スライダー

これらはすべてHTMLとCSSだけで実装しており、JavaScriptから身を護っています。
コードの細かい内容は載せませんが、デベロッパーツールで実装の内容を確認できるので、ぜひ覗いてみてください。
以降は各実装のポイントを解説します。

## ドロワーメニュー
ボタンを押したら、横からヌルっと出てくるようなアレです。
よくある実装方法の例として、ドロワーメニューを開くボタンを押した際に、JavaScriptでドロワーメニューを表示するクラスを付与する方法が挙げられます。
そしてその方法で立ちはだかるJavaScriptは、`<input type="checkbox">`で退けることができます。
アニメーションが不要な場合、実装に必要な最低限のコードは以下の通りです。
```html
<!-- ドロワーメニューを開くボタン（本当はボタンじゃないけど） -->
<input type="checkbox" />

<!-- ドロワーメニュー -->
<div>
  ドロワーメニュー
</div>
```
```css
div {
  /* デフォルトでドロワーメニューを非表示 */
  display: none;
}

/* <input type="checkbox" />にチェックが入っている場合、 */
input:checked ~ div {
  /* ドロワーメニューを表示 */
  display: block;
}
```
もう気づきましたか。
`<input type="checkbox">`と`input:checked {}`を使えば、なんだか色々できそうだと。
その通りです。
このチェックボックスを使った技"チェクボ拳"こそが、JavaScriptから身を護るための必殺技です。

## モーダルダイアログ
ドロワーメニューと並ぶUI界のスーパースターであるモーダルダイアログの実装においても、JavaScriptから身を護ることができます。
```html
<!-- モーダルダイアログを開くボタン（本当はボタンじゃないけど） -->
<input type="checkbox" />

<!-- モーダルダイアログ -->
<div>
  モーダルダイアログ
</div>
```
```css
div {
  /* デフォルトでモーダルダイアログを非表示 */
  display: none;
}

/* <input type="checkbox" />にチェックが入っている場合、 */
input:checked ~ div {
  /* モーダルダイアログを表示 */
  display: block;
}
```
もう気づきましたか。
ドロワーメニューの実装と全く同じだということを。
その通りです。
"チェクボ拳"を使えば、ドロワーメニューもモーダルダイアログも対応できます。
上記のコードには書いていないですが、"表示する位置が画面の端か中央か"ぐらいの違いしかないです。

ただしドロワーメニューと比較すると、モーダルダイアログのこの実装はHTMLのセマンティックさに欠けると感じる人がいるかもしれません。
HTMLには`<dialog>`という、名前からしてモーダルダイアログの実装にピッタリっぽいタグがあります。
`<dialog>`の主要な機能として以下が挙げられます。

- 例えば`z-index: 9999;`の要素があったとしてもダイアログの方が前面に表示される
- ダイアログを開いたときにダイアログ内のフォーカス可能な要素にフォーカスする
- ダイアログが開いている状態でEscキーを押すとダイアログが閉じる

このように機能が豊富な`<dialog>`ですが、これらを扱うにはJavaScriptが必要になります。
多少のJavaScriptとの接触に耐えられる自信がある人は、`<dialog>`を使用するとよいでしょう。
「あらゆるJavaScriptを退けるぞ！」という信念をお持ちの人は、"チェクボ拳"を使いましょう。

## ドロップダウン
HTMLの`<details>`を使えば、めちゃんこシンプルにドロップダウンを実装できます。
```html
<details>
  <!-- ドロップダウンの開閉ボタン -->
  <summary>ドロップダウンを開く</summary>
  <!-- ドロップダウンの中身 -->
  <div>メニュー1</div>
</details>
```
```css
details {
  position: relative;
}

div {
  position: absolute;
  top: 100%;
  left: 0;
}
```
`<details>`はいわゆるアコーディオンメニューの実装に最適なタグかと思いますが、アコーディオンを開いたときに表示する要素を浮かせるだけで、ドロップダウンを実装できます。

ただし、ドロップダウンの要素を非表示にする際のアニメーションは、2025年9月時点では一部のブラウザでしか実装できません。
ドロップダウンを閉じるときのアニメーションがどうしても今すぐ必要な人は、唇を噛み締めながらJavaScriptを使用しましょう。
あと"おま環"か実装の問題かもですけども、デモンストレーションの実装だとアニメーションが発生しないときがあるので、動作の安定性に欠けます。

## フィルタリング
これは"チェクボ拳"と兄弟的な関係の技"ラジオ拳"を使うことで、JavaScriptから身を護ることができます。
```html
<input type="radio" name="filter" class="filter1">
<input type="radio" name="filter" class="filter2">
<p class="group1">グループ1</p>
<p class="group2">グループ2</p>
```
```css
/* filter1のラジオボタンにチェックが入っている場合、 */
/* group1を表示 */
.filter1:checked ~ .group1 {
  display: block;
}
/* group2を非表示 */
.filter1:checked ~ .group2 {
  display: none;
}

/* filter2のラジオボタンにチェックが入っている場合、 */
/* group1を非表示 */
.filter2:checked ~ .group1 {
  display: none;
}
/* group2を表示 */
.filter2:checked ~ .group2 {
  display: block;
}
```
"チェクボ拳"と大きく異なる点は、inputのtypeが"checkbox"ではなく"radio"なところぐらいです。
あとは"チェクボ拳"と同じ要領で、"ラジオ拳"を繰り出すことができます。

なお、デモンストレーションの実装は単一の条件で絞りたい場合の実装ですが、複数の条件で絞りたい場合は"チェクボ拳"を使いましょう。

## リアルタイムバリデーション
リアルタイムでユーザーの入力を監視しなければならないので、JavaScriptが必要そうだと感じますよね。
大丈夫です。
JavaScriptから身を護りつつユーザーの入力を監視して、ただちにバリデーションのメッセージを表示することができます。
```html
<input type="text" pattern=".{1,10}" placeholder=" " required>
<p>あかんで</p>
```
```css
/* バリデーションのメッセージはデフォルトで非表示 */
p {
  display: none;
}

/* バリデーションに引っ掛かったら、メッセージを表示 */
input:not(:placeholder-shown):invalid + p {
  display: block;
}
```
inputに`pattern=".{1,10}"`と書くことで、"入力値が1～10文字ではない"場合、CSSの`:invalid`が適用されます。
ただし初回表示時は何も入力していない状態なので、入力値が1文字未満としてバリデーションに引っ掛かってしまいます。
ということで、バリデーションのメッセージの表示条件として`:not(:placeholder-shown)`を設定しています。
これによりバリデーションのメッセージを表示する条件が、"プレースホルダーが見えていないとき（つまり何かしら入力されているとき）、かつpatternにマッチしない場合"になります。
そしてinputに`placeholder=" "`を設定することで、初回表示時は"patternにはマッチしないが、プレースホルダーが見えている状態"になるので、バリデーションのメッセージが表示されないわけです。

とはいえ10文字を超えて入力されたくない場合は、inputに`maxLength="10"`を設定することで対応できます。
10文字を超えて入力されたくないのであれば、入力できる文字数の上限を10文字にすればいいのです。
このリアルタイムバリデーションの活用方法はあんまり無さそうですが、例えば"以前はユーザー名は20文字まで入力可能だったが、仕様変更により10文字までになった"みたいなケースだと活きそうです。
この場合、例えばユーザーが自身の名前を編集できるページに遷移した直後にはバリデーションメッセージが表示されているので、仕様が変わったことをユーザーに知覚させやすいです。

## SPA的ページ遷移アニメーション
SPA的ページ遷移というのは、JavaScriptでDOMとかURLとかを変える方式のページ遷移を指します。
「JavaScriptから身を護ると言っておきながら、ページ遷移においてJavaScriptの介入をゆるすのか」
というJS護身流過激派からの声もありますが、
「利用するライブラリやフレームワークの都合上、仕方がない場合もあるものです」
という言葉を飲み込みつつ、謝罪をいたします。
それでも仕方なしにSPA的ページ遷移を使わざるを得ない状況においても、諦めて全てのJavaScriptを受け入れる必要はありません。
例えばページの遷移に伴うアニメーションは、HTMLとCSSで対応することができる場合があります。
以下は"すごいページだけ背景を黒くしたい"場合に、滑らかに背景色を変更する例です。
```jsx
{/* すごくないページ */}
<div className="wrap">
  <Link href="/sugoi">
    すごいページへ行く
  </Link>
<div>
```
```jsx
{/* すごいページ */}
<div className="wrap sugoi">
  <Link href="/sugokunai">
    すごくないページへ行く
  </Link>
<div>
```
```css
body {
  transition: background 1s;
}

/* bodyがクラスsugoiの要素を持つ場合、背景を黒くする */
body:has(.sugoi) {
  background: black;
  color: white;
}
```
`body:has(.sugoi)`によって、クラス`sugoi`の要素があるページに遷移すると背景が黒くなります。
"すごいページ"は`<div className="wrap sugoi">`と書いてある通りクラス`sugoi`の要素があるので、"すごいページ"に遷移すると背景が滑らかに黒くなります。

ちなみに`:has()`は、前述の"チェクボ拳"と"ラジオ拳"の弱点を補うことができます。
実は今まで隠していたのですが、"チェクボ拳"と"ラジオ拳"には弱点があります。
チェックボックスやラジオボタンが、スタイルを変えたい要素と同階層か親階層にいないと、"チェクボ拳"と"ラジオ拳"は発動できないのです。
あらためて、ドロワーメニューを実装する場合の"チェクボ拳"を確認してみましょう。
```html
<input type="checkbox" />
<div>
  ドロワーメニュー
</div>
```
```css
div {
  display: none;
}
input:checked ~ div {
  display: block;
}
```
"チェクボ拳"の肝は`input:checked ~ div`です。
これは、"チェックボックスにチェックが入ったら、チェックボックス以降の同階層のdivが対象"という意味です。
つまり以下のようにinputとdivが同階層に無い場合は、"チェクボ拳"を発動できません。
```html
<p>
  <!-- input:checked ~ divの対象となるdivが同階層に無い -->
  <input type="checkbox" />
</p>
<div>
  ドロワーメニュー
</div>
```
この弱点により、例えば"チェックボックスが複数ある場合に、それらをflexやgridで横並びに配置したい"といった場合は、"チェクボ拳"を使えない可能性があります。

そんな絶体絶命な"チェクボ拳"ですが`:has()`との合わせ技で、さきほどの状況でも"チェクボ拳"を発動できるようになります。
```html
<p>
  <input type="checkbox" />
</p>
<div>
  ドロワーメニュー
</div>
```
```css
div {
  display: none;
}
/* pがinput:checkedな要素を持っていたら、p以降のdivを表示する */
p:has(input:checked) ~ div {
  display: block;
}
```
このように`:has()`と組み合わせれば、大抵の状況で"チェクボ拳"や"ラジオ拳"を繰り出すことができます。

とはいえ`:has()`にも弱点がありまして、それは"パフォーマンス性を損なうかもしれない"ことです。
くわしくは":has performance"とか":has パフォーマンス"とかでググってください。
`:has()`は挙動から分かる通り、要素の状態を監視しています。
そして監視対象の変化に応じて、スタイルを適用する処理を行ないます。
このように捉えると、「他のCSSプロパティに比べて重そうな処理をしそうだな～」と想像できますね。
なので監視対象はできるだけ狭い範囲にした方がよさげです。
`html:has(div)`みたいな「全divを監視したるで！」ではなく、`.button:has(.text)`のように「すみません、ほんとココだけ、ココだけの監視を、何卒、、、」みたいな。

## オンボーディングツアー
サービスにアカウントを登録すると、「まずはアカウント情報を更新しよう」みたいな案内が出て、それを済ませると次は「投稿してみよう」みたいな、使い方を次々と案内をしてくれるサービスに遭遇したことはないですかね。
ここでいうオンボーディングツアーとは、そういう使い方をガイドしていくヤツのことです。
デモンストレーションでは、新技"ターゲット拳"を使用しています。
```html
<a id="start" href="#step1">スタート</a>
<a id="step1" href="#step2">次のステップ</a>
<a id="step2" href="#start">最初から</a>
```
```css
a:target::after {
  content: "←いまここ";
}
```
`:target`はURLに含まれる`#`の値と一致する`id`の値を持った要素に、スタイルを適用する疑似クラスです。
例えば`<div id="example">`という要素があり、URLが`example.com#example`になると、先述の要素にだけCSSを適用することができます。

ちなみに"ラジオ拳"でも、オンボーディングツアーを実装することが可能です。
ただし、"ラジオ拳"に比べて"ターゲット拳"の方がHTMLの構造に制約が少ないです。
オンボーディングツアーはコンポーネントを横断的に実装しなければならないケースが多い気がするので、"ターゲット拳"の方が向いていると考えられます。

そんな"ターゲット拳"には、以下の副作用があります。

- URLに`#`が付く
- ブラウザのセッションの履歴に残る

上記の副作用が人や場合によっては、弱点になるかもしれません。
"ターゲット拳"を使用するには、"URLに`#`を付け加えなければならない"という制約があります。
この制約が人によっては、「URLが変になった」や「URLに変なものを付けるな」といったネガティブな反応になることが想定できます。
付随して、ブラウザの`戻る`や`進む`の挙動も変わります。
試しに前述のデモンストレーションのオンボーディングツアーでステップ2まで進んだ後に、ブラウザの`戻る`を実行してみましょう。
おそらくステップ1がハイライトされます。
この現象も人によっては、「前のページに戻ると思ったのに、オンボーディングから抜け出せない」といった不満が出てくることが考えられます。

とはいえステップの進捗をURLで表すことができるので、ステップが長い場合は有効な手段になり得るかもしれません。
また、スマホで`戻る`の操作をスワイプで行なうことに慣れている人、かつ「ひとつ前のステップをやり直したい」といった場合では、履歴に残っている方がよさそうです。
"ターゲット拳"は、使いどころの難しい技と言えそうですね。

## トースト
ユーザーがサインインしたときに画面の端っこから「サインインしました」みたいなメッセージが出たり、フォームをサブミットしたときに「送信しました」みたいなメッセージが出るサービスあるじゃないですか。
トーストとはそれです。
以下はページ表示直後にトーストを表示する例です。
```html
<div>トースト</div>
```
```css
@keyframes toast {
  5%, 95% {
    translate: 0;
  }
  100% {
    translate: calc(100% + 1rem);
  }
}
div {
  position: fixed;
  top: 1rem;
  right: 1rem;
  translate: calc(100% + 1rem);
  animation: toast 3s;
}
```
トーストを画面外に配置しておき、`animation`で画面内に表示して、最後に画面の外へ移動させています。

ちなみに、要素を動かすときは`top`や`right`などの`position`プロパティの値ではなく、`transform`系を使った方がよい場合が多いです。
ブラウザはHTMLとCSSを表示するまでに複数の段階を踏みますが、ブラウザとCSSのプロパティによって、どの段階から処理をするかが異なります。
ブラウザごととCSSのプロパティごとの差異は、以下のページが参考になります。
https://lab.skk.moe/css-triggers
上記のページによると、`position`系の値はどのブラウザも`Layout`から処理しますが、`transform`はChromeとFirefoxにおいては`Composite`だけの処理で済みます。

## スライダー
スライダーを実装するときって、問答無用でSwiperやslickを導入していませんか。
でも"ラジオ拳"を使えば、あら不思議、ライブラリ使わずともスライダーを（ある程度）実装できます！
```html
<input type="radio" id="slide1" name="slide" checked>
<input type="radio" id="slide2" name="slide">
<ul>
  <li>1</li>
  <li>2</li>
</ul>
```
```css
ul {
  overflow: hidden;
  display: flex;
}

li {
  width: 100%;
  flex-shrink: 0;
}

#slide2:checked ~ ul li:nth-of-type(2) {
  translate: -100%;
}
```
自動でスライドしないスライダーでよければ、このようにかなりシンプルに実装できます。

対してデモンストレーションに実装してある、次のスライドまたは前のスライドを表示するボタンの設置はそこそこめんどいです。
以下はデモンストレーションのコードの抜粋です。
```html
<!-- 次のスライドを表示するボタン -->
<label for="slide3">
  ‹
</label>
<label for="slide1">
  ‹
</label>
<label for="slide2">
  ‹
</label>

<!-- 前のスライドを表示するボタン -->
<label for="slide2">
  ›
</label>
<label for="slide3">
  ›
</label>
<label for="slide1">
  ›
</label>
```
表示中のスライドごとに、"前へ"と"次へ"のボタンを入れ替えることで実装しています。
スライドの1枚目が表示されている場合、各ボタンの挙動は以下になります。
- "前へ"を押された場合: スライドの3枚目を表示
- "次へ"を押された場合: スライドの2枚目を表示

スライドの2枚目が表示されている場合、各ボタンの挙動は以下になります。
- "前へ"を押された場合: スライドの1枚目を表示
- "次へ"を押された場合: スライドの3枚目を表示

このように、表示中のスライドによって"前へ"と"次へ"の挙動が変わるので、挙動ごとにHTMLとCSSを書く必要があります。

また、CSSの`animation`を使用することで、自動でスライドさせることができます（やったことないのでたぶん）。
ただし、`<input type="radio">`の`checked`と同期させることはできないでしょうけども。
自動でスライドさせつつ、アクティブなスライドを手動で切り替えられるようにしたい場合は、残念ながらJavaScriptを使うほかありません。
人生はスライダーです。
人生をスライドしていく中で、時には己の信念をスライドしなければならないこともあります。
